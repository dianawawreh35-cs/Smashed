## Fix first

These either stop an agent working, put wrong numbers into the reports, or
break a feature outright.

**F-01. The Agent App crashes when a new customer is saved after the caller has
hung up.** `src/CallCenter.AgentApp/ViewModels/CallerViewModel.cs:504-508`.
`AfterSaveAsync` raises `FormFinished`; the handler in `CallViewModel.cs:85-93`
calls `Caller.Clear()`, which disposes `_lookup` — the same object as
`forCall`. The next line reads `forCall.Token` on a disposed source and throws
`ObjectDisposedException`. Because of F-02 that closes the app, and the phone
stops registering until someone reopens it. *Scenario:* an unknown caller rings
off, the agent fills in "save as new customer" (A-11) and presses Save.
*Fix:* take the token before raising `FormFinished`, or re-check
`ReferenceEquals(forCall, _lookup)` after it.
**Fixed 27 Sep 2026, 02e9ff0.**

**F-02. Any exception on the Agent App's UI thread ends the app.**
`src/CallCenter.AgentApp/App.xaml.cs:58-59`. `DispatcherUnhandledException`
logs and never sets `args.Handled = true`, so every faulted async command
terminates the process, mid-call if there is one. `OnStartup` is `async void`
(`:41`) with the same effect at start-up. *Fix:* mark non-fatal exceptions
handled, show a message, flush the log; add a `TaskScheduler.UnobservedTaskException`
handler.
**Fixed 27 Sep 2026, 02e9ff0.**

**F-03. Logging a call trusts the client, so an agent can rewrite or invent
calls, and a shared laptop credits one agent's calls to another.**
`src/CallCenter.Server/Features/Communications/CommunicationsService.cs:106-126`.
The row is found by `(SipCallId, Extension)` from the request body and then
overwritten, including `AgentId`, status and times. The extension is never
compared with the signed-in user's, and the A-42 edit window is not applied.
- *Deliberate misuse:* an agent replays yesterday's Missed call as Answered
  with a long talk time and improves their own R-15 figures, or invents calls
  with random Call-IDs and uploads audio for each.
- *Honest misuse:* the Agent App's offline buffer is per Windows profile, not
  per agent (`AgentBufferDbContext.cs:13-16`), and `CallLogReporter.cs:200-209`
  replays it for whoever signs in next. Agent A's evening with the server down
  becomes agent B's calls the next morning, and A's classifications for them
  come back `not_your_call` and are discarded (`CallLogReporter.cs:294-303`).

*Fix, both ends:* the server refuses an extension that is not the user's own
and never changes `AgentId` on an existing row; the Agent App stores the user
id on each `PendingUpload` and replays only the signed-in user's rows.
**Fixed 27 Sep 2026 in the Agent App, ba72292** (the server's half is its own).

**F-04. Pasting a branch's delivery price list always fails with 500 (S-58).**
`src/CallCenter.Server/Features/Delivery/DeliveryAreasService.cs:277`. It calls
`BeginTransactionAsync` directly, but the context uses `EnableRetryOnFailure`
(`Program.cs:46`), and EF refuses user-started transactions under a retrying
strategy. The only test of the route checks authorisation. *Fix:* wrap it in
`db.Database.CreateExecutionStrategy().ExecuteAsync(...)` as
`ApplicationsService.cs:157` does, and add a database test that posts an import.

**F-05. An agent's re-save un-resolves a complaint the supervisor resolved (R-17).**
`src/CallCenter.Server/Features/Classifications/ClassificationService.cs:406-414`.
The Agent App always sends `Resolved: null`
(`AgentApp/ViewModels/ClassificationFormViewModel.cs:533`), and the server copies
any value that differs from the stored one, clearing `Resolved`, `ResolvedAt`
and `ResolvedBy`. A typo fixed in the notes, or the offline queue delivering
late, puts the complaint back to unresolved. *Fix:* treat null as "leave it",
or let only supervisors change the resolved fields.

**F-06. The dashboard's "today" is an hour wrong on clock-change days, and the
next one is Saturday 24 October 2026.**
`src/CallCenter.Server/Features/Reports/ReportScope.cs:130` builds midnight
with the offset *now*, not midnight's. On 24 October the S-20 dashboard leaves
out calls from 00:00 to 01:00; on the spring change it takes in the previous
day's last hour. The end of the day at `:134` is already done right. No test
can see it: CI runs in UTC (no `TZ` in `.github/workflows/ci.yml`, while the
Dockerfile sets `Asia/Hebron`), and the test helper `CallReportsTests.cs:373-377`
copies the same formula. *Fix:* `TimeZoneInfo.Local.GetUtcOffset(local.Date)`;
set `TZ: Asia/Hebron` on the CI test job and add a clock-change case.

**F-07. The backup script reports success on an empty dump, and that empty
file replaces the night's good one.** `deploy/backup.sh:21,26,29`. `set -e`
without `pipefail` means `pg_dump | gzip` succeeds whenever gzip does. With the
db container down, a 20-byte `db-<date>.sql.gz` is written, "backup OK" is
printed and `update.sh` carries on; the same file name overwrites the 03:30
dump locally and on `/mnt/backup`. Separate from N-07, and it will matter the
day N-07 is fixed. *Fix:* `set -Eeuo pipefail`, write to a temporary file,
`gzip -t` it, rename; put the time in the name.

**F-08. One stuck item stops the Agent App's upload queue for ever.**
`src/CallCenter.AgentApp/Services/CallLogReporter.cs:306-316`. Anything not on
the discard list ends the pass and is retried without limit. Two ways in: a
recording upload is held to the 10 s `HttpClient.Timeout`
(`ServerOptions.cs:18`) while the file grows about 1 MB a minute, and a 400
from model validation has no `code` and comes back as `server_error` (for
example a caller name over `LogCallRequest`'s 200 characters). After one long
call on weak Wi-Fi, nothing more from that laptop reaches the server. *Fix:*
cap the attempts and move the item aside; carry on with the next item (keeping
call-before-classification order); give uploads their own long timeout.
**Fixed 27 Sep 2026, ba72292.**

**F-09. Race conditions in `CallService` can leave the phone permanently busy.**
`src/CallCenter.AgentApp/Services/Calls/CallService.cs`.
- `:599-617` (`AnswerAsync`) and `:461-500` (`DialAsync`): Connected is set
  after the answer returns without checking the call still exists. If the BYE
  lands in between, `Finish` has already set Idle and `Set` builds Connected
  from it. The pop-up hides, but the service stays Connected and answers every
  later INVITE 486 Busy (`:914-944`), logged Missed, with no Hang up button.
  *Plausible* as a race; the code path is verified.
- `:655-681`: Cancel during dialling sets `_hangingUpLocally` and returns without
  clearing it. If the customer answers in that moment, their later BYE is
  ignored and the same busy state follows.
- `:578-595` against `:1372-1380`: with auto answer, `AnswerAsync` and
  `PrepareMedia` race and the prepared media session and audio endpoint are
  overwritten, never closed — about one audio device handle leaked per call.

*Fix:* make each transition under `_gate` and only if the state and call id
still match; close any media that loses the race.
**Fixed 27 Sep 2026, f4f7670.**

**F-10. POS-created customers are never counted as new in R-16.**
`src/CallCenter.Server/Features/Reports/ReportCube.cs:291` counts a customer as
new only when `created_by IS NOT NULL`, meant to leave out the seeded customer
book. `Features/Pos/PosCustomerSync.cs:206-212` also creates contacts with no
`created_by`. Once `POS_LOOKUP_TOKEN` is set, "new customers" drifts towards
zero. *Fix:* mark seeded contacts explicitly (a source column) instead of
inferring it.

**F-11. A-03, a Must, is not built: the agent cannot choose microphone, speaker
or ring device.** `AgentSettingsStore.cs:29-33` has the fields; nothing reads or
writes them, there is no screen, and `CallService.cs:1397` always opens the
Windows defaults. The runbook (`DEPLOY-server-runbook.md:434`) tells the
installer to choose them. With a USB headset and built-in speakers the call can
go to the wrong device.
**Not built: A-03 removed at Dia's request, 27 Sep 2026, 64a6744.** The headset
is made the Windows default instead (runbook step 10).

**F-12. The login can be hammered without limit.**
`Features/Auth/AuthController.cs:18-20`; no `AddRateLimiter` anywhere. Each
attempt costs a BCrypt check (100-200 ms of CPU), unknown users included. Anyone
on the LAN can guess passwords freely, or send a few dozen at once and slow the
API for every agent. *Fix:* the built-in rate limiter on the login route, per
IP and per login.

**F-13. The `.env.example` placeholder secrets pass start-up validation.**
`change-me-to-a-long-random-string` is 33 characters and satisfies
`[MinLength(32)]` (`Features/Auth/JwtOptions.cs:18`); `SipSecretProtector.cs:45-57`
accepts any non-blank key. An installer who forgets two lines runs with keys
that are public in git. *Fix:* refuse any value containing `change-me` or equal
to the development keys.

**F-14. The queue open/closed state can end up inverted** *(plausible trigger)*.
`Features/Pbx/PbxQueueSwitch.cs:232-245` runs the `*280` toggle on the request's
cancellation token. Closing the tab after the PBX has answered throws
`OperationCanceledException`, which is not caught, so the PBX has toggled and
the stored state has not; the next press flips it the wrong way. *Fix:* once the
PBX answers, finish and save on `CancellationToken.None`.
